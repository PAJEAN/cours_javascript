Étape 11 : Highscore

Casse-briques · étape 11 sur 13 · durée estimée : 30 min à 1 h

Objectif

Conserver le meilleur score même quand on ferme ou recharge la page, et l'afficher sous le canvas ainsi que sur l'écran de fin. Pour cela, on utilise le localStorage du navigateur.

📝 Étape optionnelle pour la classe débutante

Cette étape est facultative si vous êtes en retard : votre jeu est déjà complet à l'étape 10. Elle est courte et ne dépend que de la classe Jeu ; vous pouvez la faire si vous avez du temps, ou passer directement aux missions bonus.

📖 Dans le cours
  • L'interactivité : le localStorage (getItem, setItem, JSON.stringify / JSON.parse).
  • Trouver les éléments du document (afficher une valeur dans la page).

Ce qu'il faut savoir du localStorage

  • Il enregistre des paires clé / valeur qui survivent au rechargement de la page.
  • Les valeurs sont toujours des chaînes de caractères : un nombre enregistré revient en texte, il faut le reconvertir (Number).
  • Si la clé n'existe pas encore (première partie), getItem renvoie null : le programme doit prévoir ce cas.

Vous pouvez voir ce qui est enregistré dans les outils de développement (touche F12, onglet Application, puis Local Storage) et même supprimer la clé pour retester la « première partie ».

11.1 Lire le meilleur score

Au démarrage du jeu (dans le constructeur de Jeu, pas dans initialiserPartie() : le record ne doit pas être remis à zéro à chaque nouvelle partie), on lit le record enregistré. Le nom de la clé est une constante, pour éviter une faute de frappe qui ferait chercher à deux endroits différents.

À toi de jouer.

constante CLE_RECORD = un nom de clé (par exemple 'casse-briques-record') dans le constructeur de Jeu : attribut record = valeur enregistrée sous CLE_RECORD, convertie en nombre (0 si rien n'est enregistré)
Indice 1

Le cours montre exactement ce cas : lire une valeur, la convertir avec Number(...) et prévoir une valeur par défaut avec ||. Affichez this.record dans la console pour vérifier.

Indice 2

Number(null) vaut 0 et Number(undefined) vaut NaN ; or NaN || 0 vaut 0 : la valeur par défaut couvre donc aussi les cas bizarres.

11.2 Enregistrer un nouveau record

Quand la partie se termine (méthode terminer(), appelée aussi bien pour une victoire que pour une défaite), on compare le score au record. S'il est meilleur, c'est un nouveau record : on le mémorise dans l'objet et dans le localStorage. On retient aussi, dans un attribut nouveauRecord, qu'un record vient d'être battu pour pouvoir le féliciter sur l'écran de fin. Cet attribut est remis à false au début de chaque partie.

À toi de jouer.

initialiserPartie() : attribut nouveauRecord = faux terminer(message) : (le code existant : etat = 'fin', message…) si score > record : record = score nouveauRecord = vrai enregistrer record sous CLE_RECORD
Indice

On enregistre uniquement si le score bat le record, jamais sinon : sans cette condition, un mauvais score écraserait le meilleur. setItem prend la clé et la valeur (le nombre est converti en chaîne automatiquement).

11.3 Afficher le meilleur score

Deux endroits : dans la page HTML, sous le canvas, une ligne « Meilleur score : … » dont la valeur est mise à jour par JavaScript (on retrouve l'élément par son id) ; et sur l'écran de fin dans le canvas, qui rappelle le score, le record, et félicite si nouveauRecord est vrai.

À toi de jouer.

dans index.html : sous les boutons, un paragraphe "Meilleur score : " avec un élément (id record) qui contiendra la valeur dans le constructeur de Jeu : récupérer cet élément, l'enregistrer dans un attribut (afficheRecord) afficher le record lu en 11.1 dans l'élément dans terminer(), quand un record est battu : mettre à jour le texte de l'élément dans dessinerEcran(), cas 'fin' : si nouveauRecord : "Nouveau record : (valeur du record) !" + consigne pour rejouer sinon : "Score : (score) (record : (record))" + consigne pour rejouer
Indice 1

Pour afficher une valeur dans un élément, on modifie son contenu avec textContent (ou innerHTML comme dans le cours). Comme l'élément est utilisé à plusieurs endroits, il vaut mieux le récupérer une seule fois, dans le constructeur.

Indice 2

Pour construire le texte, concaténez avec + : 'Score : ' + this.score. Le choix entre deux textes s'écrit avec un if / else ou avec un ternaire.

Checklist de validation

Jouez plusieurs parties, puis rechargez la page entière :

  • Au premier chargement (ou après suppression de la clé), le meilleur score affiché est 0.
  • Après une partie avec un score supérieur, le meilleur score se met à jour dans la page et l'écran de fin annonce un nouveau record.
  • Après rechargement (F5), le meilleur score est toujours là.
  • Une partie avec un score inférieur ne change pas le record.
  • Une nouvelle partie (Espace) ne remet pas le record à zéro, mais remet bien nouveauRecord à faux.
  • Le record est un nombre et non du texte (testez jeu.record + 1 dans la console).
  • La console ne contient aucune erreur en rouge.

Erreurs fréquentes

  • Le record « se concatène » ("90" + 10 donne "9010") ou la comparaison est fausse : la valeur lue n'a pas été convertie en nombre avec Number. Comparer deux chaînes revient à les classer par ordre alphabétique ("9" > "10").
  • Le record affiche null ou NaN : première lecture sans valeur par défaut.
  • Le record est perdu au rechargement : setItem n'est jamais appelé, ou la clé utilisée pour lire n'est pas exactement la même que pour écrire (faute de frappe, majuscules).
  • Le record revient à zéro à chaque nouvelle partie : il est lu dans initialiserPartie() au lieu du constructeur.
  • Un mauvais score écrase le record : l'enregistrement n'est pas dans le if (score > record).
  • Cannot set properties of null (setting 'textContent') : l'élément n'a pas été trouvé ; vérifiez l'id dans le HTML et dans getElementById.
  • Le record est différent entre deux navigateurs, ou entre une page ouverte en file:// et avec Live Server : le localStorage est propre à chaque site et à chaque navigateur. C'est normal.
