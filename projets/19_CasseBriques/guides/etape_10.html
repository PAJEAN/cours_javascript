Étape 10 : Menu, pause, rejouer

Casse-briques · étape 10 sur 13 · durée estimée : 45 min à 1 h 30

Objectif

Le jeu démarre aujourd'hui dès que la page s'ouvre et, pour rejouer, il faut recharger la page. Vous allez lui donner de vrais écrans : un écran titre avant la partie, une pause (touche P et bouton), et la possibilité de rejouer sans recharger la page.

Cette étape se code dans la classe Jeu écrite à l'étape 9 (les classes Raquette, Balle et Brique ne changent pas). Classe débutante : l'essentiel est le système d'états (10.1 à 10.4) avec le clavier ; les boutons HTML sont facultatifs.

📖 Dans le cours
  • L'interactivité : le gestionnaire d'événements (addEventListener, click).
  • Les événements du clavier (keydown, event.key).
  • Trouver les éléments du document (récupérer un bouton).
  • Les attributs simples (par exemple disabled d'un bouton).
  • switch (une valeur, plusieurs cas).
  • Écrire du texte dans un canvas.

Un état plutôt que des booléens

À l'étape 9, une seule information indique si la partie avance : enCours (vrai ou faux). Avec un écran titre et une pause, deux valeurs ne suffisent plus, et ajouter un booléen par situation (enPause, enMenu…) mène vite à des combinaisons impossibles (« en pause et terminé » ?). On utilise à la place un seul attribut, etat, qui contient une chaîne parmi quatre : 'menu', 'jeu', 'pause' ou 'fin'. À tout instant, le jeu est dans un et un seul état.

La boucle continue alors de tourner en permanence (pour pouvoir afficher le menu ou la pause), mais seul l'état 'jeu' fait avancer la partie.

10.1 Les états du jeu

Le booléen enCours disparaît complètement : chaque endroit qui le lisait ou le modifiait utilise maintenant etat. On change aussi l'affichage : selon l'état, un voile semi-transparent recouvre le jeu avec un titre et une consigne. Une fonction à switch choisit quoi écrire.

À toi de jouer. Dans Jeu :

initialiserPartie() : attribut etat = 'menu' (remplace enCours) terminer(message) : etat = 'fin' (remplace enCours = faux) boucle() : si etat vaut 'jeu' : mettreAJour() effacer le canvas dessiner() redemander une image TOUJOURS (plus de condition sur enCours) dessinerTexte(titre, sousTitre) : voile noir semi-transparent sur tout le canvas écrire le titre au centre, le sous-titre juste dessous dessinerEcran() : (remplace dessinerMessage) selon etat : 'menu' : titre du jeu + consigne (Espace pour jouer, flèches, P pour la pause) 'pause' : "PAUSE" + consigne pour reprendre 'fin' : le message (GAGNÉ / PERDU) + consigne pour rejouer 'jeu' : rien dessiner() : appeler dessinerEcran() à la place de dessinerMessage()
Indice 1

Pour un voile semi-transparent, utilisez une couleur rgba(0, 0, 0, 0.6) : le dernier nombre est l'opacité. Dessinez-le avant le texte (sinon il le cacherait). Pensez à repasser fillStyle en blanc pour le texte.

Indice 2

Un switch sur this.etat avec un case par état, chacun terminé par break. Faites une recherche dans votre fichier du mot enCours : il ne doit plus apparaître nulle part (sauf dans un éventuel commentaire).

10.2 Écran titre et lancement

Au chargement, le jeu est dans l'état 'menu' : la balle ne bouge pas. Il faut un déclencheur pour passer à 'jeu' : la barre d'espace ou la touche Entrée, et un bouton « Jouer » dans la page (facultatif). On regroupe la logique dans une méthode lancer(), appelée par le clavier et par le bouton : ainsi, une même action est écrite une seule fois.

Un bouton se crée dans index.html, avec un id pour le retrouver depuis game.js (voir le cours). On lit le bouton dans le constructeur de Jeu, dans un attribut (par exemple this.boutonJouer), et l'écouteur click est branché dans une méthode ecouterBoutons().

À toi de jouer.

dans index.html (facultatif) : sous le canvas, un bouton "Jouer" (id btn-jouer) dans Jeu : constructeur : récupérer le bouton, puis ecouterBoutons() méthode lancer() : si etat n'est ni 'menu' ni 'fin' : ne rien faire sinon : etat = 'jeu' ecouterClavier() : à l'appui sur Espace ou Entrée : (empêcher le défilement de la page) puis lancer() ecouterBoutons() : clic sur le bouton Jouer : lancer()
Indice 1

Dans evt.key, la barre d'espace s'écrit ' ' (un espace entre guillemets) et non 'Space'. Pour empêcher la page de défiler quand on appuie sur Espace, il faut evt.preventDefault().

Indice 2

Le garde « ne rien faire si l'état n'est ni 'menu' ni 'fin' » est important : sans lui, appuyer sur Espace pendant la partie la relancerait. Écrivez-le en première instruction de lancer() avec un return anticipé.

10.3 La pause

La pause bascule entre deux états : 'jeu' devient 'pause' et inversement. Dans les autres états (menu, fin), appuyer sur P ne doit rien faire. Comme la boucle n'appelle mettreAJour() que dans l'état 'jeu', la partie se fige toute seule : il n'y a rien d'autre à écrire pour l'arrêter.

Un bouton « Pause » peut changer de texte (« Reprendre ») et être désactivé quand il ne sert à rien. On change le texte d'un élément avec textContent (comme innerHTML dans le cours, mais pour du texte simple), et on le désactive avec l'attribut disabled (true / false).

À toi de jouer.

dans index.html (facultatif) : un bouton "Pause" (id btn-pause) à côté du bouton Jouer dans Jeu : méthode basculerPause() : si etat vaut 'jeu' : etat = 'pause' sinon si etat vaut 'pause' : etat = 'jeu' ecouterClavier() : à l'appui sur P (minuscule ou majuscule) : basculerPause() ecouterBoutons() : clic sur le bouton Pause : basculerPause() facultatif : méthode mettreAJourBoutons() : bouton Jouer : texte "Rejouer" si etat vaut 'fin', sinon "Jouer" ; désactivé pendant 'jeu' et 'pause' bouton Pause : texte "Reprendre" si etat vaut 'pause', sinon "Pause" ; désactivé en 'menu' et 'fin' (à appeler à chaque changement d'état)
Indice 1

La touche P donne 'p' ou 'P' dans evt.key selon la touche Majuscule : testez les deux (avec ||).

Indice 2

Pour mettre à jour les boutons à chaque changement d'état, appelez mettreAJourBoutons() dans tous les endroits où etat est modifié (initialiserPartie, lancer, basculerPause, terminer). Pour une condition « texte A ou texte B », l'opérateur ternaire condition ? a : b est pratique (voir le cours).

10.4 Rejouer

À l'étape 8.4 (et 9.4), « rejouer » rechargeait la page. On veut maintenant repartir d'une partie neuve sans recharger : tout ce qui décrit une partie (balle, raquette, briques, score, vies, message) doit être recréé. Vous avez déjà une méthode qui fait exactement cela : initialiserPartie().

À toi de jouer.

lancer() : si etat n'est ni 'menu' ni 'fin' : ne rien faire si etat vaut 'fin' : initialiserPartie() (partie neuve) etat = 'jeu' supprimer le rechargement de la page (document.location.reload) de ecouterClavier()
Indice

initialiserPartie() remet etat à 'menu' : il faut donc passer à 'jeu' après l'avoir appelée. Si, au lieu de recommencer, la partie se termine tout de suite, c'est qu'un attribut (le nombre de vies, le message…) n'est pas réinitialisé dans initialiserPartie().

Checklist de validation

Rechargez la page, puis cochez :

  • Au chargement, l'écran titre s'affiche avec la grille derrière et la balle immobile.
  • Espace (ou Entrée, ou le bouton) lance la partie.
  • P (ou le bouton) met le jeu en pause : tout est figé, « PAUSE » s'affiche ; P reprend là où on s'était arrêté.
  • P ne fait rien sur l'écran titre ni sur l'écran de fin.
  • Appuyer sur Espace pendant la partie ne la relance pas.
  • En fin de partie (gagnée ou perdue), l'écran de fin s'affiche, et Espace relance une nouvelle partie complète (score à zéro, toutes les vies, toutes les briques) sans recharger la page.
  • Le mot enCours n'existe plus dans le code ; un seul attribut, etat, décrit l'état.
  • La console ne contient aucune erreur en rouge.

Erreurs fréquentes

  • La partie démarre toute seule : l'état initial n'est pas 'menu', ou mettreAJour() est appelée sans tester etat === 'jeu'.
  • L'écran reste vide après la fin (ou le canvas ne se redessine plus) : la boucle s'arrête si requestAnimationFrame n'est plus appelé quand l'état n'est pas 'jeu'. Il doit être appelé à chaque tour, dans tous les états.
  • L'erreur etat is not defined : il manque this. devant etat.
  • Rien ne se passe en comparant des états : = affecte, === compare. if (this.etat = 'jeu') écrase l'état au lieu de le tester. Vérifiez aussi l'orthographe des chaînes ('pause' et pas 'Pause').
  • Espace relance le jeu ou le met en pause « tout seul » : après un clic, le bouton garde le focus et la barre d'espace le « clique » à nouveau. Appelez blur() sur le bouton après le clic.
  • Espace relance la partie en pleine partie : lancer() doit tester l'état en première instruction et sortir si on n'est ni dans 'menu' ni dans 'fin'.
  • La nouvelle partie reprend avec l'ancien score ou les anciennes briques : initialiserPartie() ne recrée pas tous les attributs.
  • Les touches fléchées ne répondent plus après un clic sur un bouton : le focus est sur le bouton ; blur() règle aussi ce problème.
⭐ Missions bonus
  • ★★ Compte à rebours « 3, 2, 1 » avant de lancer la balle : ajoutez un état (par exemple 'compte') ou un attribut, et utilisez setTimeout / setInterval (voir les minuteurs). Dessinez le chiffre au centre du canvas ; la partie commence quand le compte atteint zéro.
