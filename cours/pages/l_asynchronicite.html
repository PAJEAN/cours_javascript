L'asynchronicité

JavaScript est un langage monothread : il n'exécute qu'une seule instruction à la fois. Si une opération longue (comme un appel réseau ou la lecture d'un fichier) bloque le fil d'exécution, l'application entière devient inutilisable. Pour éviter cela, JavaScript repose sur l'asynchronicité : certaines opérations sont exécutées en arrière-plan, et leurs résultats sont traités plus tard, sans bloquer l'interface.

Les minuteurs (setTimeout et setInterval)

La façon la plus simple de différer une action est d'utiliser un minuteur. Le navigateur se charge d'attendre, puis appelle la fonction de rappel (callback) fournie, sans bloquer le reste du programme.

  • setTimeout(fonction, delai) exécute la fonction une seule fois après delai millisecondes.
  • setInterval(fonction, delai) exécute la fonction de façon répétée, toutes les delai millisecondes.
  • Ces deux fonctions retournent un identifiant à passer à clearTimeout(id) ou clearInterval(id) pour annuler le minuteur.
📝 À savoir

Le délai est un minimum : si le thread principal est occupé, la fonction s'exécute plus tard. Pour animer un dessin à l'écran, il existe un outil plus adapté, requestAnimationFrame(), présenté dans le chapitre Le dessin et les canvas.

Les promesses (Promises)

Une promesse est un objet qui représente la valeur d'une opération asynchrone, mais qui n'est pas encore disponible au moment de sa création. Elle peut être dans l'un des trois états suivants :

  • pending : en attente, l'opération est en cours.
  • fulfilled : terminée avec succès, la promesse renvoie une valeur.
  • rejected : échouée, la promesse renvoie une erreur.

Lorsqu'une promesse est résolue (fulfilled ou rejected), on peut accéder à son résultat via les méthodes .then() (succès) et .catch() (erreur).

Les promesses sont aujourd'hui la base de l'asynchronicité en JavaScript. Elles sont utilisées par de nombreuses API modernes, comme fetch(). Elles peuvent aussi être utilisées avec async/await pour convertir une opération asynchrone en code synchrone.

Vous pouvez exploiter la méthode Promise.all([]) pour exécuter plusieurs promesses en parallèle et attendre que toutes soient terminées (ou qu'une échoue).

Les appels AJAX

Les appels AJAX (Asynchronous JavaScript & XML) permettent de communiquer entre le client et le serveur de manière asynchrone, c'est-à-dire sans rechargement complet de la page. Historiquement, on utilisait pour cela l'objet XMLHttpRequest (XHR), mais dans les applications modernes, on préfère la méthode fetch(), plus simple et plus puissante.

La méthode fetch(url, options) permet d'envoyer une requête HTTP. Elle renvoie une promesse qui sera résolue lorsque la réponse du serveur est disponible. Par défaut, fetch() effectue une requête GET, mais il est possible de configurer d'autres méthodes (POST, PUT, DELETE…) via l'objet options.

📝 À savoir

fetch() permet aussi de charger un fichier de votre propre projet (par exemple fetch('niveaux.json')). Cela ne fonctionne pas si la page est ouverte directement depuis le disque (file://) : le navigateur bloque la requête. Il faut servir la page via un serveur local, par exemple avec l'extension VS Code Live Server (clic droit sur le fichier HTML puis Open with Live Server).

L'objet Response ne contient pas directement le corps de la réponse en JSON mais fournit une représentation de l'ensemble de la réponse HTTP. Aussi, pour extraire le corps en JSON de l'objet Response, on utilise la méthode json(), qui renvoie une deuxième promesse dont la résolution fournit le résultat de l'analyse du corps de la réponse au format JSON (developer.mozilla.org).

💡 Exercice

A partir d'une liste d'URLs d'API publiques ("https://jsonplaceholder.typicode.com/todos/1", "https://jsonplaceholder.typicode.com/todos/2" et "https://jsonplaceholder.typicode.com/todos/3") :

  • Écrire une fonction chargerDonnees(urls) qui prend en paramètre le tableau d'URLs.
  • Utiliser fetch pour récupérer les données de chaque URL.
  • Attendre que toutes les requêtes soient terminées avec Promise.all.
  • Afficher les résultats dans la console (ou sur la page HTML).

Les Web Workers

Les Web Workers permettent de déléguer des calculs lourds à un autre thread, laissant le thread principal fluide pour l'utilisateur. Il fonctionne dans un environnement isolé et n'a pas accès directement au DOM (document, window…). L'échange avec la page principale se fait via un système de messages.
